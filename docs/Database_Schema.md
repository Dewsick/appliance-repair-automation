# Структура базы данных

В проекте используются пять таблиц для хранения информации о клиентах, сотрудниках, заявках и взаимодействиях.

## 1. Clients

Хранит информацию о клиентах.

| Поле | Тип данных | Назначение |
|---|---|---|
| `id` | Number | Уникальный идентификатор клиента |
| `name` | String | Имя клиента |
| `phone` | String | Номер телефона |
| `email` | String | Электронная почта |
| `city` | String | Город клиента |
| `created_at` | Date | Дата создания записи |
| `last_contact_at` | Date | Дата последнего контакта |

## 2. Employees

Хранит информацию о сотрудниках сервиса.

| Поле | Тип данных | Назначение |
|---|---|---|
| `id` | Number | Уникальный идентификатор сотрудника |
| `name` | String | Имя сотрудника |
| `specialization` | String | Специализация по ремонту |
| `phone` | String | Контактный телефон |
| `telegram_id` | String | Telegram ID сотрудника |
| `active` | Boolean | Доступен ли сотрудник для назначения |
| `created_at` | Date | Дата создания записи |

## 3. Requests

Хранит заявки на ремонт бытовой техники.

| Поле | Тип данных | Назначение |
|---|---|---|
| `id` | Number | Уникальный номер заявки |
| `client_id` | Number | Идентификатор клиента |
| `description` | String | Описание обращения |
| `device_type` | String | Тип бытовой техники |
| `brand` | String | Производитель техники |
| `problem` | String | Описание неисправности |
| `priority` | String | Приоритет заявки |
| `status` | String | Текущий статус заявки |
| `preferred_date` | Date | Желаемая дата визита |
| `preferred_time_from` | String | Начало желаемого интервала |
| `preferred_time_to` | String | Конец желаемого интервала |
| `assigned_employee_id` | Number | Идентификатор назначенного сотрудника |
| `created_at` | Date | Дата создания заявки |
| `updated_at` | Date | Дата последнего изменения заявки |

## 4. Interactions

Хранит историю взаимодействий с клиентами.

| Поле | Тип данных | Назначение |
|---|---|---|
| `id` | Number | Уникальный идентификатор взаимодействия |
| `client_id` | Number | Идентификатор клиента |
| `request_id` | Number | Идентификатор заявки |
| `channel` | String | Канал взаимодействия |
| `direction` | String | Направление сообщения |
| `message` | String | Текст сообщения или описание события |
| `created_at` | Date | Дата создания записи |

## 5. pending_actions

Хранит временные данные для обработки ожидающих действий сотрудников.

| Поле | Тип данных | Назначение |
|---|---|---|
| `id` | Number | Уникальный идентификатор записи |
| `employee_telegram_id` | String | Telegram ID сотрудника |
| `request_id` | Number | Идентификатор заявки |
| `action` | String | Ожидаемое действие |
| `created_at` | Date | Дата создания записи |
| `message_id` | Number | Идентификатор сообщения Telegram |

## Связи между таблицами

- `Requests.client_id` ссылается на `Clients.id`.
- `Requests.assigned_employee_id` ссылается на `Employees.id`.
- `Interactions.client_id` ссылается на `Clients.id`.
- `Interactions.request_id` ссылается на `Requests.id`.
- `pending_actions.request_id` ссылается на `Requests.id`.

## Примечание

Документ описывает логическую структуру данных проекта. Для публикации используются названия полей и их назначение без реальных персональных данных.
